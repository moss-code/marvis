# 小马办公室 · 标准演示剧本

> 演示前请先运行 **设置 → 演示自检**，确保 6 项全绿；上传 `assets/demo/电信业务数据.xlsx`（或 `npm run make-demo` 生成后上传）。**也支持 csv / txt**：回归材料见 `assets/demo-multi/`。

## 多格式数据（M6）

除电信演示 xlsx 外，可上传 **xlsx / xls / csv / txt** 表格数据：

| 文件 | 用途 |
|---|---|
| `assets/demo-multi/学生成绩-utf8.csv` | UTF-8 中文列名 |
| `assets/demo-multi/学生成绩-gbk.csv` | Excel 默认 GBK 导出 |
| `assets/demo-multi/学生成绩-bom.csv` | UTF-8 BOM |
| `assets/demo-multi/学生成绩-tab.txt` | Tab 分隔 |
| `assets/demo-multi/学生成绩-comma.txt` | 逗号分隔 |
| `assets/demo-multi/普通文章.txt` | 应被拒绝（非表格） |

上传后可问：「分析一下各班级数学成绩排名并出报告。」

## 数据资源（M7）

对话区 chip 只显示**已选中的数据资源**（Active），可点 **×** 移出对话（不删库）。点击 **「选择数据」** 从全部表中勾选；设置 → 数据 可物理删除表或「加入/移出对话」。

彩排混表时：在「选择数据」里只勾选电信三张表，或 × 掉不需要的 chip。

## 开场白（约 30 秒）

「这是**小马办公室**——一个多 Agent 协作的桌面演示产品。您只和**领队马**对话，它会像主管一样把任务派给数据马、报表马、文书马、文件马等手下。整个过程在 Pixi 场景里实时演出：派单、干活、出报告、归档，任务日志全程透明。今天我们用一份电信营业厅数据，走一遍从分析到报告再到归档的闭环。」

## 演示前检查

1. 设置 → **演示自检** 六项全绿（环境、模型、数据表、MCP、工作区、报告引擎）
2. 已上传电信 xlsx，对话区可见数据表 chip
3. 可选：清空 `%APPDATA%/pony-office/pony-office.db` 避免旧对话干扰（重新生成 demo 数据后建议执行）
4. 音效 🔊 已开（可演示静音 🔇）
5. 投影分辨率 ≥ 1280×800

## 第 1 问：分析各营业厅业务表现并出一份报告

**老板的话：** 分析各营业厅业务表现并出一份报告

**预期演出：** 领队马派单 → 数据马 SQL + 键盘声 → 报表马 render_report → 白板贴纸 + 纸张声 → 领队汇总

**验证链路：** data → report 串联、白板、ECharts

**兜底话术：** 若未上传数据，领队应提醒先上传 xlsx，不编造数字。

---

## 第 2 问：哪个营业厅问题最大？结合投诉数据找原因

**老板的话：** 哪个营业厅问题最大？结合投诉数据找原因

**预期演出：** 数据马多表分析；应指向**老城厅**下滑 + 装维类投诉偏高（与 demo 故事线一致）

**验证链路：** 多表 JOIN、故事线呈现

**兜底话术：** 若结论模糊，可追问「请给出具体投诉量和环比」。

---

## 第 3 问：根据分析写一份月度总结邮件草稿

**老板的话：** 根据分析写一份月度总结邮件草稿

**预期演出：** 派给文书马；若绑定 skill-email，正文应符合邮件规范（主题/称呼/三段式/落款）

**验证链路：** writer + skill-email 技能注入

**兜底话术：** 若尚未做第 1、2 问，先补跑分析再写邮件。

---

## 第 4 问：把刚才的报告归档到工作区

**老板的话：** 把刚才的报告归档到工作区

**预期演出：** 文件马 export_report_file；若文件已存在弹出**覆盖确认框**

**验证链路：** file 马 + export_report_file + 确认框

**兜底话术：** 若无报告，领队应说明需先生成报告。

---

## 第 5 问：分析一下各营业厅的离职率（数据中不存在）

**老板的话：** 分析一下各营业厅的离职率

**预期演出：** 数据马查询后**优雅拒绝**；领队如实说明「数据中没有离职率/HR 指标」，**不编造**

**成功标准：** 连续 3 次均不编造数字、不假装已分析

**兜底话术：** 「当前上传的数据只有业务、用户增长和投诉，没有 HR 离职率字段。」

## 加场环节（可选）

1. **现场招聘**：招聘一只自定义马（皮肤 + Skill + MCP），问一个与 Skill description 相关的问题，验证领队按技能标签派单
2. **高德 MCP**：为自定义马绑定 amap-maps，问「从 A 到 B 怎么走」

## 风险预案

| 风险 | 应对 |
|---|---|
| 断网 / 模型超时 | 自检「模型连通」失败；对话有明确错误，应用不崩溃 |
| API Key 缺失 | 自检「环境配置」红叉 + 修复提示 |
| 投影分辨率低 | 全屏 1440×900 或缩放 UI |
| 旧对话干扰 | 删除 userData 下 pony-office.db 后重启 |

## 附录：调优记录（失败案例 → prompt 修改）

| 问题 | 现象 | prompt 修改 |
|---|---|---|
| 第 5 问编造离职率 | 模型幻觉出百分比 | dataSystem 增加「无 HR 指标禁止编造」；leaderSystem 第 9 条强化 |
| 领队不派单 | 直接回答「已分析」 | 已有 shouldRequireDispatch + prepareStep 督办（M3） |
| 报表马缺数据 | 报告图表空白 | leader 派 report 时 brief 须附完整数据（M2 规则） |

**调优完成标准：** 第 1–4 问每问连续 3 次成功；第 5 问连续 3 次优雅拒绝。
