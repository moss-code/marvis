## 1. 接口增量

### 1.1 共享类型（src/shared/types.ts）

```ts
/** 演示自检单项结果 */
export interface SelfCheckItem {
  name: string            // 如「模型连通」
  ok: boolean
  detail: string          // 通过时为摘要（如模型名/表数量），失败时为可操作的修复提示
}
```

### 1.2 IPC（src/shared/ipc.ts）

| channel | 方向 | 签名 | 说明 |
|---|---|---|---|
| `app:selfCheck` | invoke | `() => SelfCheckItem[]` | 串行跑完全部检查再返回（总耗时 ≤10s，单项超时按失败计） |

`WindowApi` 新增 `selfCheck(): Promise<SelfCheckItem[]>`。preload 两文件同步。

### 1.3 新内置工具 read_skill_reference（所有绑定了含 references 的 Skill 的小马）

```ts
read_skill_reference({ skill: string, file: string }) => { content: string } | { error: string }
```

- `file` ∈ 该 Skill 实际存在的 reference 文件名（`reference.md` / `examples.md`）；校验逻辑与 `run_skill_script` 的 allowed 集合同构（未绑定的 skill / 不存在的文件返回 error）。
- 返回内容截断至 ≤20000 字符（尾部加「…（已截断）」）。
- 照常发 `tool_call_started/finished`（tool='read_skill_reference'）。
- **音效与自检不新增任何 AgentEvent**；音效是事件流的第三个消费视图（动画、日志之后），订阅渲染进程已有的 dispatch 分发即可。

## 2. 音效系统规范（src/renderer/src/audio/AudioDirector.ts，新模块）

### 2.1 架构

- 单例 `AudioDirector`，在 `App.tsx` 的事件分发处与 SceneDirector 并列调用 `audioDirector.handle(ev)`。
- 全部声音用 **Web Audio API 程序合成**（OscillatorNode + 滤波白噪声 + GainNode 包络），不引入任何音频文件。
- 主音量 GainNode 统一 0.12~0.18；开关状态存 `localStorage('pony-sound')`，**默认开**；标题栏加 🔊/🔇 切换按钮（与「动画演示」按钮同区）。
- 主进程 `createWindow` 前加 `app.commandLine.appendSwitch('autoplay-policy', 'no-user-gesture-required')`，避免 AudioContext 被自动播放策略挂起（坑位 1）。

### 2.2 事件 → 音效映射

| 事件 | 音效设计（合成参数建议） | 时长 |
|---|---|---|
| run_started | 轻快双音上行（sine 660→880Hz，各 90ms） | 0.2s |
| task_dispatched | 木质「嗒」（三角波 220Hz 短脉冲 + 快速衰减） | 0.12s |
| tool_call_started | 进入键盘敲击循环：带通滤波（~2.5kHz）白噪声短爆发，随机间隔 70~140ms | 持续 |
| tool_call_finished / task_completed / task_failed | 停止该小马的键盘循环 | —— |
| task_completed | 上行三音琶音（C-E-G，sine，柔和） | 0.35s |
| task_failed | 下行双音（330→247Hz，音量更低，不刺耳） | 0.4s |
| report_ready | 纸张沙沙（白噪声 0.3s，带通 1.5~3kHz，三角包络）+ 轻「叮」 | 0.5s |
| run_finished | 轻柔单音钟声（sine 880Hz + 长衰减泛音） | 0.8s |

实现约定：键盘循环按 `pony` 维度管理（Map<PonyId, loopHandle>），`run_finished` 时强制清空全部循环（兜底）；同类音效 200ms 内去重（多 tool call 连发时不炸耳）；mute 状态下 handle() 直接 return，不创建任何节点。

### 2.3 环境底噪（可选加分项）

开关打开时播放极低音量（gain ≤0.02）的 brown noise 底噪营造办公室氛围；与事件音共用主开关。实现成本低（一个 ScriptProcessor/AudioWorklet 或预生成 noise buffer 循环），若影响性能可砍。

## 3. 场景光影与演出打磨（src/renderer/src/scene/）

红线：所有打磨项不得让场景掉出 60fps（用 dev 模式下 Pixi ticker FPS 验证）；单项实现 ≤80 行，超了就简化。

| 项 | 设计 | 实现要点 |
|---|---|---|
| 小马影子 | 每只马脚下椭圆软影（半透明 ink 色），行走时跟随，working 时轻微缩放 | PonyActor 内 Graphics 椭圆，挂在最底层 |
| 吊灯光晕呼吸 | 3 盏吊灯光晕 alpha 在 0.06~0.14 正弦呼吸，相位错开 | buildWorld 中保留光晕引用，ticker 中更新 |
| 窗光尘埃 | 窗光区域 10~14 个微粒（2~3px 圆，alpha ≤0.3）缓慢漂浮 + 闪烁 | 单 Container + ticker 位移，出界回绕 |
| 笔记本屏幕闪烁 | 小马 working 时其工位笔记本屏幕颜色轻微闪烁（模拟打字） | OfficeScene 暴露 `setDeskActive(id, on)`，SceneDirector 在 tool_call_started/finished 调用 |
| 白板报告徽标 | 报告 ≥2 份时贴纸右上角显示黄铜圆徽 + 数字 | pinReport 已有贴纸，加 Text 徽标 |
| 解雇/入场补光 | 入场时新马位置短暂高光淡出（替代彩带，保持克制） | animate() 一次性 Graphics |

## 4. Skill / MCP 体验完善

### 4.1 references 按需读取（行为变更，最重要）

- `prompts.ts` 的 `formatSkillBlock` **不再全文注入 references**，改为只列清单：

```
### 可用参考文件（用 read_skill_reference 按需读取，skill="<id>"）
- reference.md
- examples.md
```

- 子马执行器在 `buildPonyAgent` 中：绑定的 Skill 含 references 时合入 `read_skill_reference` 工具（见 1.3）。
- SKILL.md 正文（markdown 字段）维持全文注入不变。

### 4.2 花名册带技能标签

`describeRoster` 与 `leaderSystem` 的花名册行追加技能摘要，让领队马依据 description 派单：

```
· to=custom-abc12345（导游马，自定义）：规划旅行路线…
  技能：高德地图查询（查 POI/路线/天气）；归档命名规范（按日期命名归档文件）
```

格式：`技能：<name>（<description 截断至 40 字>）`，分号分隔；无技能不输出该行。MCP 绑定同理可加 `工具源：filesystem、amap-maps`（一行，仅 server name）。

### 4.3 设置页交互修缮（SettingsPanel.tsx）

1. **测试结果挂行**：`testResult` 改为 `Map<serverId, string>`（state 用 `Record<string, string>`），显示在对应 server 行下方，互不覆盖。
2. **JSON 实时校验**：MCP 编辑 textarea onChange 时 try-parse，错误即时显示红字（不阻塞输入）；保存按钮在 parse 失败时禁用。
3. **Skill 编辑器预览**：编辑区右侧（或 tab 切换）复用 `MarkdownBody` 渲染预览；正文下方显示字符计数 `n / 2000`。
4. **脚本徽标**：Skill 列表、PonyCard 与招聘表单的 Skill 勾选项中，含 `scripts` 的 Skill 显示「⚙ 含脚本」徽标（title 提示「该技能可执行本地脚本并联网」）。
5. **references 徽标**：同上显示「📄 含参考文档」（轻量，纯展示）。

## 5. 演示数据与 prompt 调优

### 5.1 演示数据增强（scripts/make-demo-xlsx.mjs）

生成 3 个 sheet（每表 ≥60 行，月度 6 个月 × 8~10 个营业厅），数据**内置故事线**便于讲解：

| sheet | 列 | 故事线 |
|---|---|---|
| 营业厅业务月报 | 营业厅、月份、宽带新装、套餐办理、5G升级 | 「城东厅」连续 3 月高增长；「老城厅」持续下滑 |
| 用户增长 | 营业厅、月份、新增用户、流失用户、净增 | 「老城厅」流失加速，与业务下滑互相印证 |
| 投诉明细 | 营业厅、月份、投诉类别、投诉量、处理时长 | 「老城厅」装维类投诉显著偏高（解释下滑原因） |

数值带合理噪声但趋势清晰，保证模型「一查就能讲出故事」。

### 5.2 标准演示剧本（5 问，写入 docs/演示剧本.md）

| # | 老板的话 | 验证链路 |
|---|---|---|
| 1 | 分析各营业厅业务表现并出一份报告 | data → report 串联、白板、ECharts |
| 2 | 哪个营业厅问题最大？结合投诉数据找原因 | 多表 JOIN 分析、故事线呈现 |
| 3 | 根据分析写一份月度总结邮件草稿 | writer + skill-email 技能注入效果 |
| 4 | 把刚才的报告归档到工作区 | file 马 + export_report_file + 确认框 |
| 5 | 分析一下各营业厅的离职率（数据中不存在） | 失败兜底：如实说明无此数据，不编造 |

### 5.3 docs/演示剧本.md 结构

开场白（30 秒产品叙事）→ 演示前检查（见第 6 节）→ 5 问逐条（话术 + 预期演出 + 兜底话术）→ 加场环节（现场招聘小马 + 绑高德 MCP 问路线）→ 风险预案（断网/模型超时/投影分辨率）。

## 6. 演示自检（app:selfCheck）

主进程实现检查项（串行，单项 try-catch，**任何一项异常都不能让整体抛错**）：

| name | 检查内容 | 失败 detail 示例 |
|---|---|---|
| 环境配置 | `.env` 三项非空 | 「OPENAI_API_KEY 未配置，复制 .env.example 为 .env 并填写」 |

## 9. 已知坑位（务必避开）

1. **AudioContext 自动播放策略**：Chromium 默认要求用户手势后才能出声。主进程 `app.whenReady()` 之前加 `app.commandLine.appendSwitch('autoplay-policy', 'no-user-gesture-required')`；保险起见 AudioDirector 在首次 handle() 时检查 `ctx.state==='suspended'` 则 `resume()`。
2. **键盘循环泄漏**：tool_call_finished 与 task_completed/failed 都要停循环，且 run_finished 兜底清空；漏停的循环会在静音后仍占用调度（mute 只是 gain=0 的话）。mute 实现为「不创建节点」而非「音量置零」。
3. **打磨项的 ticker 开销**：尘埃/呼吸/闪烁全部合并进**现有** ticker 回调，禁止新增多个 `app.ticker.add`；Graphics 不要每帧 clear+重绘（用 alpha/position/scale 属性动画）。
4. **read_skill_reference 的截断**：reference 可能几百 KB，必须截断（≤20000 字符）再回喂；同时 `tool_call_finished.resultSummary` 仍按 200 字符截断，两层互不影响。
5. **自检的模型连通项**：必须设独立 5s 超时（AbortSignal），否则断网时整个自检卡死；自检期间禁止并发触发 chat:send（设置面板运行自检时禁用对话输入即可，复用 running 提示样式）。
6. **asar 与子进程**：filesystem MCP server 必须 `asarUnpack`，spawn 时把路径中的 `app.asar` 替换为 `app.asar.unpacked`（electron-builder 解包后的实际位置）；echarts 的 `readFileSync` 走 Electron 补丁后的 fs，可直接读 asar 内文件，**不要**改用 `original-fs`。
7. **打包后的 .env**：见第 7 节加载顺序；便携版把 `.env` 放在 exe 同目录即可，演示机迁移时记得一起拷。
8. **中文 productName**：NSIS 安装路径含中文一般无碍，但 `artifactName` 用 ASCII（`pony-office-${version}.exe`），避免传输/校验环节出幺蛾子。
9. **演示数据重新生成后**：旧库中 `data_` 表是 DROP 重建，但**对话历史里的旧分析结论还在**；彩排前清一次 userData 下的 `pony-office.db`（或提供「清空对话」按钮，可选加分项）。
