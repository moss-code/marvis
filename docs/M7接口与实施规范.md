# 小马办公室 M7 接口标准与实施规范（对话数据资源集）

> 前序见 [M6接口与实施规范.md](./M6接口与实施规范.md)。本阶段引入 Inventory / Active 两层数据资源模型。
> **接口事实源**：`src/shared/types.ts`、`src/shared/ipc.ts`；AgentEvent 协议冻结。

## 0. 产品模型

| 概念 | 含义 | UI |
|---|---|---|
| Inventory | SQLite 全部 `data_*` 表 | 设置 → 数据 |
| Active | 用户勾选、Agent 可见子集 | 对话 chip + 选择数据面板 |

- chip **×**：移出 Active，不删库
- 设置 **删除**：物理删表 + 移出 Active
- **上传**：新表追加到 Active

## 1. 共享类型

```ts
export interface DataResourceState {
  tables: TableSchema[]
  activeTables: string[]
}
```

## 2. IPC 增量

| channel | 签名 |
|---|---|
| `db:getActiveTables` | `() => string[]` |
| `db:setActiveTables` | `(names: string[]) => DataResourceState` |

`uploadXlsx` 返回扩展：`{ tables, activeTables }`

`chat:send` 签名不变；主进程 `startRun` 时 `resolveActiveTables()`。

## 3. 持久化

`app_meta` 表，key=`active_tables`，value=JSON 数组。

首次无记录且有表 → 默认 Active = 全部表名。

## 4. Agent

`resolveActiveTables()` 替代 `listDataTables()` 注入 prompt。

## 5. UI

- ChatDock：Active chip + ×、「选择数据」、`DataPicker`
- Settings：已加入对话徽标、加入/移出对话

## 6. 验收标准

- [ ] 默认迁移：老库 Active = 全部表
- [ ] chip 仅 Active；× 不删库
- [ ] 选择数据面板勾选正确
- [ ] 上传追加 Active
- [ ] 设置删表同步 Active
- [ ] Active 为空时领队提醒
- [ ] 运行互斥
- [ ] `npm run typecheck` 通过
